## 2. Диагностика и выявление коренной причины (Root Cause)
- Логирование через SOFA_DIAG на эмуляторе LDPlayer9 в сети Ростелеком:
  - DNS-резолвинг: api.sofascore.com успешно разрешается в IP-адреса Fastly за 400-600 мс.
  - TCP-соединение: Успешно устанавливается за 1-3 мс.
  - TLS-рукопожатие: Успешно проходит за 180-840 мс (TLS 1.2, ECDHE-RSA-CHACHA20-POLY1305).
  - Вывод по провайдеру: Ростелеком не блокирует api.sofascore.com.
- Сравнительные тесты сетевых клиентов:
  - Вариант 1 (Cronet + Chrome 124 UA): HTTP 403 Forbidden (Server: Varnish / Fastly WAF).
  - Вариант 2 (OkHttp + Chrome 124 UA): HTTP 403 Forbidden (Server: Varnish / Fastly WAF).
  - Вариант 3 (OkHttp + Chrome 134 UA): HTTP 403 Forbidden (Server: Varnish / Fastly WAF).
  - Вариант 4 (OkHttp + честный okhttp/4.12.0 UA): HTTP 200 OK (Server: nginx, 12 live-событий, 44 КБ данных).
  - Вариант 5 (OkHttp HTTP/1.1 + честный UA): HTTP 200 OK.
- Выявленные причины:
  1. WAF Fastly блокирует запросы из Java/OkHttp, если они маскируются под браузер Chrome (несоответствие TLS-отпечатка и User-Agent).
  2. Режим по умолчанию relay1 использовал адрес sub.mimumi.mikata.ru, который недоступен и приводил к зависанию на 16+ секунд при запуске.

### 4.2. android/app/src/main/java/mgks/os/swv/SofaScoreClient.java
- Переключен currentConnectionMode по умолчанию на direct.
- Очищен устаревший адрес configuredRelayUrl.
- Метод handleLiveAction: убран тяжелый диагностический запуск runDiagnosticExperimentOnce из стартового потока; переведен на отказоустойчивую ротацию зеркал fetchWithMirrors.

- Заменен спуфинговый User-Agent Chrome 124 на легитимный okhttp/4.12.0 во всех сетевых методах (fetchViaRelay, fetchViaProxy, openConnection).
- Метод handleTestConnection: переведен на вызов fetchWithMirrors.

### 4.3. app.js и android/app/src/main/assets/app.js

### 4.4. android/app/src/main/assets/index.html и index.php
